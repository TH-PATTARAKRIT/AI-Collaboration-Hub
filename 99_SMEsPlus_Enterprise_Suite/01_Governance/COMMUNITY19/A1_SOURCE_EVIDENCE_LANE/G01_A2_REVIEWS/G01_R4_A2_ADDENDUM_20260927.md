```
'depends': ['website', 'mail'],
```

There is **no** `portal` entry in `website_mail`'s `depends` list. No edge `website_mail → portal` exists at the anchor. The word "confirmed here" in the R2A A2 addendum was written over a manifest that was never fetched by that addendum's own scratch trail (per the A3 R2A recheck §1.2, confirmed absent from `blob_log_r2a.txt`). ## 2. `google_recaptcha` — R2B-1 (citation-only fix)

### 2.1 What was wrong

The R2B A2 addendum's T6 row (§1) cited the screen-default-read behaviour as living in `res.config.settings.get_values`, called on `res_config.py`. This addendum independently locates the actual code path rather than accepting A3's assertion at face value.

### 2.2 Independent verification (this session)

Fetched `odoo/addons/base/models/res_config.py` at the anchor (§0.3; blob `504644162d067988dd7d3dcb90cd7e1a065c9fc3`, matching the R2B addendum's and the A3 R2B recheck's own X5 citation) and read both candidate methods directly:

- `get_values` (base `res.config.settings` class): a two-line stub whose docstring says it returns values for fields other than `default`/`group`/`module`, and whose body is `return {}`. It performs **no** `ir.config_parameter` read and contains no reference to `field.default`.
- `default_get` (same class, defined immediately after `get_values`): calls `super().default_get(fields)`, then for each field classified as a `config`-parameter field executes `IrConfigParameter.get_param(icp, field.default(self) if field.default else False)` — this is the exact line that, for `recaptcha_min_score` (which declares `default="0.7"` in `addons/google_recaptcha/models/res_config_settings.py`, independently re-fetched in this session, blob `c2f237bba64c4147098c610cc41348806a58af7d`), returns `"0.7"` when the stored parameter is absent, which the subsequent `float` branch converts to `0.7` for display. `default_get` ends by calling `res.update(self.get_values())`, so `get_values` (the stub above) contributes nothing to this specific value.

This session's own read confirms A3's finding independently: the field-default screen-read path is in `default_get`, not `get_values`. `get_values` on the base class returns `{}` and has no bearing on this behaviour.

**Corrected citation (T6, supersedes the R2B A2 addendum's method name only; the observed behaviour and verdict are unaffected):**

> **T6 correction (google_recaptcha).** "Screen read path — source pointer: X5 `res_config.py`, **`default_get`** (not `get_values`). `IrConfigParameter.get_param(icp, field.default(self) if field.default else False)`: when the field has a default and the stored parameter is absent, `get_param` returns that default, `"0.7"`, which the float branch then converts to `0.7`. The screen therefore shows `0.7` while the enforced runtime gate (T4) is `0.0`/off. `get_values` on the base `res.config.settings` class is a two-line stub (`return {}`) and is not the source of this behaviour; `default_get` calls it at the end (`res.update(self.get_values())`) but `get_values` contributes nothing to the `recaptcha_min_score` value itself."

No other T-row, no Lane A erratum content, and no REC-RCAP-09R1/10R1/11R1 disposition is affected. This is a citation-only correction of a method name; the substantive content (T1–T9, all still CONFIRMED against this session's own independent read of the same files) is unchanged.
