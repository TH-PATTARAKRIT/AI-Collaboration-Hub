## 4. Semantic / business findings

- **SF-W01 (material, export governance).** The export-permission group is a server-enforced gate on the platform's export-data method, and the CSV/XLSX routine depends on that method. A1's framing ("bulk-export permission may exist only as a UI/client convention") would lead downstream design to believe export is uncontrolled. It is controlled.
- **SF-W02 (residual export semantics).** Three points. (a) Three sources of truth disagree: the client flag reflects the group only, export-data admits the group or the Access-Rights admin, and JSON admits the group only. An Access-Rights admin without the group can export but may see the feature hidden. (b) An export whose record set is empty never calls export-data, so it returns a header-only file without the group check, and the audit log line is still written. (c) The export group governs the export method, not data egress. The generic search-read API returns the same data to any user with read rights, and the pivot XLSX route formats client-supplied data with no group check. A design should not treat "cannot export" as "cannot extract".
- **SF-W03 (DB manager authority).** Database lifecycle authority is a server-wide secret plus a server flag, and it is independent of tenant identity. Disabling listing disables the whole management surface, not only enumeration.
- **SF-W04 (first-use takeover, X-WEB-02).** On a server with management enabled and the default secret, the first unauthenticated POST that carries a secret sets the master secret and persists it. The manager page render also receives a flag saying whether the secret is still the default (OM-W03).
- **SF-W05 (content route semantics).** Token presence controls shared-cache eligibility. Access comes from token verification, the content-return hook, or normal read ACLs and rules. A1's wording could be misread as "a token grants public access".
- **SF-W06 (onchange exemption).** The user-model exemption skips the access check for any existing user record, and the skip is not tied to self-edit. Onchange does not persist data, so the impact is bounded to computed values being returned. The breadth still matters to a redesign.
- **SF-W07 (profiling).** Profiling authority is time-boxed and database-wide, not per-user. Collectors and parameters come from the client. The base source comments say this may be dangerous.
- **SF-W08 (company hierarchy).** Session info deliberately exposes the names and structure of ancestor companies the user cannot access. In a tenant-isolated design this is an information disclosure within a tenant, not across tenants.
- **SF-W09 (logo route).** C14 is confirmed as a cross-company read that bypasses the ORM, limited to one image field. In a multi-tenant deployment on one database, company ids are enumerable integers.
