## 7. Rule-4/5 self-correction — adjudication (the most important finding in this re-check)

**What PROOF R2C discloses (its own §0.1, rule 5 row, and §1 predeclaration record):** two reconnaissance passes over the same nine files exist in scratch — one starting **16:28:45Z** (`src/`), producing its own **`predeclared_R2C.ts` = 16:30:05Z** and **`exec_R2C.txt` = 16:30:18Z**, and a second (`src_proof_r2c/`) — both made *before the official cases file existed* and, critically, *before REC R2C was frozen* (D1-level REC re-freeze **16:35:40Z**; REC R2C's own consumption-hash **16:36:30Z**). The addendum's stated correction: it wrote an **official** predeclaration hashed **16:36:53.10Z** (after REC froze) and re-fetched into a fresh directory (`src_proof_r2c_official/`) starting **16:37:01.48Z**, closing execution at **16:37:13.52Z**. Every blob recomputed identically across all three passes. The addendum frames this as "the same pattern B3B Proof R1 disclosed at its §1 for its own 15:36:51Z owner-stage read" and argues "nothing turns on which pass is cited" because each case keeps a fail branch.

**This framing is a mischaracterization, and the self-correction does not restore rule 4/5 compliance in substance.**

1. **The two disclosed defects are not equivalent to the B3B R1 precedent.** B3B R1's accepted item was a *different stage's* (A2's) ordinary owner-stage source read at 15:36:51Z — A2 is expected to read source as part of its normal re-derivation work, and that read naturally happens before REC freezes and before Proof predeclares; it is not itself a Proof predeclare/execute cycle. Here, the artifacts named — `predeclared_R2C.ts` and, especially, **`exec_R2C.txt`** — are PROOF-stage predeclaration-and-execution artifacts, i.e. this stage ran its *own* full predeclare-then-execute cycle prematurely. That is a different and more serious event than an upstream stage reading files.

2. **Both practices this reconnaissance repeats are the exact practices C1-B already ruled prohibited**, per `MASTER_CONTROLLED_HANDOFF_STATE_20260927_C1B.md` §"Systemic process findings": *rule 4* — "REC finalised after PROOF and citing PROOF — REC must be frozen (sha256 recorded) before PROOF **executes**"; *rule 5* — "Predeclaration evidence relied on mtimes in some runs — cases file sha256 + UTC timestamp must be written before first source fetch." The reconnaissance pass violates **both**, independently: (a) its own fetch (16:28:45Z) preceded its own predeclaration (16:30:05Z) — the literal opposite of rule 5's requirement; and (b) its execution closed (16:30:18Z) roughly **five minutes before REC froze** (16:35:40Z / 16:36:30Z) — a direct rule 4 violation (Proof executed before REC was frozen), not merely before Proof's *own* predeclaration. C1-B's language calls these patterns "prohibited," not "acceptable if later disclosed and redone."

3. **The "official" redo cures the paperwork, not the epistemic contamination.** By the time the official predeclaration text was authored (16:36:53Z), the actual content of every cited file and the actual PASS outcome of every case were already known from the 16:30 execution. Predeclaration exists specifically so that expected/fail criteria are committed *before* the evidence is seen, precluding after-the-fact tailoring. Re-fetching into a fresh directory and getting identical blobs does not establish that the officially-declared expected/fail text was written blind — it only shows the source did not change between fetches, which was never in doubt. "Each case keeps a fail branch" is a necessary safeguard but not a sufficient one, since a fail branch can itself be shaped with knowledge of what the source will not show.

4. **This is inconsistent with the same batch's own harder standard.** RES-M3 (§3.4 above) treats an analogous ordering problem — the D1-level mail REC classifying items partly on the basis of already-executed Proof D1 results, discovered by A3-MD-19 — as a genuine defect requiring *bounded independent re-derivation* of the affected items, not as cured by disclosure alone. Applying disclosure-only acceptance to PROOF R2C's own, more direct violation (an actual premature predeclare-execute cycle, not merely an upstream stage's file read) while requiring substantive re-derivation for RES-M3's analogous case is an inconsistent standard within the same batch.

**Ruling:** the rule-4/5 self-correction claim in PROOF R2C §0.1/§1 is a **rationalization, not a procedurally sound cure**. This does **not** overturn the factual PASS results of PC-MAIL-R2-01/02/03/04 — this reviewer independently re-derived all four from a fresh, unprompted anchor read (§3.3, §3.5) and could not refute any of them; the underlying source facts are true regardless of the predeclaration defect. What is not established is that the *official* PROOF R2C record was blindly predeclared as C1-B's rule 4/5 require. **New residual RES-C1** is opened on this basis (§8).
