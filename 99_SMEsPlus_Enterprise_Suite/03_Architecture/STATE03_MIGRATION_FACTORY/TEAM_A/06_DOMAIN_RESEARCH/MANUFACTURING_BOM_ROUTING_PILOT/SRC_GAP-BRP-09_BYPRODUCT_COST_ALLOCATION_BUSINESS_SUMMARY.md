## 1. คำตอบสั้น

Odoo 19 **มีกลไกปันส่วนต้นทุนให้ By-Product แบบตั้งค่าเองเป็นเปอร์เซ็นต์** เรียกว่า **"Cost Share (%)"** ระบุที่แต่ละบรรทัด By-Product ใน BoM:

- ผู้ใช้เป็นคนกำหนด % เอง — ระบบ **ไม่ได้คำนวณให้อัตโนมัติ** จากมูลค่าตลาด จำนวน หรือน้ำหนัก
- ตอนปิด MO (ผลิตเสร็จ) ระบบเอา **ต้นทุนผลิตรวม** ไปแบ่ง: By-Product ได้ตาม % ที่ตั้ง, **สินค้าหลักได้ส่วนที่เหลือ (100% − ผลรวม % ของ By-Product ทั้งหมด)**
- ถ้า **ไม่ตั้ง % (ปล่อยเป็น 0)** → By-Product เข้าสต็อกที่ **มูลค่า 0** และสินค้าหลักแบกต้นทุนทั้งก้อน 100%

ดังนั้น "ไม่ปันต้นทุนเลย" ที่พบในแหล่งข้อมูลระดับ V1 เมื่อก่อน **เป็นผลลัพธ์ของการที่ผู้ใช้ไม่ได้กรอก %** ไม่ใช่กฎตายตัวของระบบ — และ Odoo 19 ไม่มีการเตือนใดๆ เมื่อปล่อยเป็น 0 (ดูความเสี่ยงข้อ 5)

## 2. ต้นทุนรวมที่ถูกนำไปแบ่งประกอบด้วยอะไร

ต้นทุนรวมของ MO = (1) มูลค่าวัตถุดิบที่ถูกใช้ไปจริง + (2) ต้นทุน Work Center/แรงงานตามเวลาที่บันทึก + (3) "Extra Unit Cost" (ต้นทุนเพิ่มต่อหน่วยที่กรอกที่ MO) × จำนวนที่ผลิต

- ค่านี้คำนวณ **ทุกครั้งที่มีการผลิตและปิดยอด** (รวมกรณีผลิตบางส่วนแล้วเปิด backorder — Extra Unit Cost ถูกคัดลอกไป backorder)
- ต้นทุนต่อหน่วยของ By-Product = ต้นทุนรวม × (% ของบรรทัดนั้น ÷ 100) ÷ จำนวนที่ผลิตได้จริง
- ต้นทุนต่อหน่วยของสินค้าหลัก = ต้นทุนรวม × (1 − ผลรวม %) ÷ จำนวนที่ผลิตได้จริง
- ผลิต By-Product เกินแผน: ต้นทุนรวมของ By-Product ยังเท่าเดิมตาม % แต่ราคาต่อหน่วยลดลง (เพราะหารด้วยจำนวนจริง)

## 3. กฎควบคุมที่ระบบบังคับ

| กฎ | ระบุที่ |
|---|---|
| % ต้องไม่ติดลบ | ทั้งที่ BoM และที่ MO |
| ผลรวม % ของ By-Product ทั้งหมดต้อง **ไม่เกิน 100** | ทั้งที่ BoM (ตรวจแยกทุก variant) และที่ MO (ไม่นับบรรทัดที่ยกเลิก) |
| ผลรวม **ไม่จำเป็นต้องเท่ากับ 100** — ส่วนที่ไม่ได้แบ่งตกที่สินค้าหลัก | ไม่มีกฎบังคับให้ครบ 100 |
| By-Product ห้ามเป็นสินค้าเดียวกับสินค้าหลักของ BoM | ทั้งที่ BoM และตอนสร้าง MO |
| ต้องเปิดฟีเจอร์ By-Products ในการตั้งค่าก่อน | เป็นกลุ่มสิทธิ์ (feature toggle) |
| % ตั้งได้ 2 ตำแหน่งทศนิยม | ออกแบบไว้เพื่อความถูกต้องของการปัดเศษ |

**MO แก้ % ได้เองหรือไม่:** ทุก MO คัดลอก % มาจาก BoM ตอนสร้าง และ % นั้น **เป็นฟิลด์ที่ปรากฏบนบรรทัด By-Product ของ MO** (ซ่อนเป็นค่าเริ่มต้น เปิดได้ผ่านตัวเลือกคอลัมน์) — เมื่อ MO ถูกผูก/เปลี่ยน BoM ระบบ sync ค่า % จาก BoM มาใส่บรรทัด By-Product ของ MO ให้ ทั้งนี้ เอกสารนี้ **ไม่ได้ยืนยันว่า MO ที่ปิดแล้วแก้ % ย้อนหลังได้หรือไม่** (ดูข้อ 7)

## 4. พฤติกรรมตามวิธีคิดต้นทุนของสินค้า (Costing Method)

| ชนิดต้นทุนของ **By-Product** | ชนิดต้นทุนของ **สินค้าหลัก** | ผลที่เกิดขึ้น |
|---|---|---|
| FIFO / Average | FIFO / Average | ปันส่วนตาม % ตามข้อ 2 — ยอดรวมเข้าสต็อกเท่ากับต้นทุนผลิต ไม่มีมูลค่าหาย |
| **Standard** | FIFO / Average | By-Product เข้าที่ **ราคามาตรฐานของตัวเอง** (ไม่สนใจ %), แต่สินค้าหลัก **ยังถูกหัก %** ออก → ผลรวมมูลค่าที่เข้าสต็อกอาจไม่เท่าต้นทุนผลิต (ส่วนต่างไปค้างที่บัญชีของ Production location — *เป็นข้อสรุปจากกฎการลงบัญชี ไม่ได้ทดสอบโดยตรง*) |
| ใดๆ | **Standard** | สินค้าหลักเข้าที่ราคามาตรฐาน — **% ไม่มีผลต่อมูลค่าที่ลงสต็อก** ต้นทุนจริงที่ต่างจากมาตรฐานไม่ถูกส่งต่อไปที่ By-Product |

> Odoo มี test ของตัวเองยืนยันทั้งสามกรณี (ดู Evidence) — ผู้ออกแบบ Odoo ตั้งใจให้ "% ยังถูกหักจากสินค้าหลักเสมอ เพื่อไม่ให้มูลค่าหายไปจากสต็อก" กรณี Standard By-Product + FIFO สินค้าหลัก

## 5. ความเสี่ยงทางธุรกิจ / การควบคุมที่ต้องระวัง (สำหรับ STATE03 Migration)

1. **ไม่ตั้ง % = ต้นทุนสินค้าหลักสูงเกินจริง + By-Product มูลค่าศูนย์** (ยืนยัน candidate risk เดิม แต่เกิดจากการตั้งค่า ไม่ใช่ default ของระบบ) — ไม่มี warning, ไม่มีการบังคับให้รวมครบ 100
2. **คอลัมน์ Cost Share ซ่อนเป็นค่าเริ่มต้น** ทั้งบน BoM และบน MO → ผู้ใช้ทั่วไปมองไม่เห็นว่ามีฟิลด์นี้
3. **Migration**: BoM/By-Product ที่นำเข้าจากระบบเก่าต้องมีค่า % ถูกนำเข้าด้วยอย่างชัดเจน มิฉะนั้นทั้งหมดจะกลายเป็น 0 และมูลค่าสต็อกหลังย้ายจะเพี้ยนทันทีที่มีการผลิตครั้งแรก — เป็น **ข้อกำหนดข้อมูลที่ต้องใส่ใน Migration Factory**
4. **การมี Standard-cost ปนกับ FIFO/AVCO ในสาย BoM เดียวกัน** ทำให้ยอดไม่ balance ตามข้อ 4 แถว 2 — ควรกำหนดนโยบายให้สอดคล้องกัน
5. **Landed Cost บน MO**: By-Product ที่ % เป็น 0 **ถูกตัดออก** ไม่รับ landed cost ส่วนที่ปันมาเลย (ตั้งใจออกแบบและมี test)
6. **รายงาน**: รายงานภาพรวม MO และรายงานโครงสร้าง BoM แสดงต้นทุนที่ปันให้ By-Product ตาม % ; ส่วน "Cost Breakdown" ของ MO **ข้าม By-Product ที่ % เป็น 0**
7. **ปุ่ม "คำนวณราคาจาก BoM"** (สำหรับสินค้า Standard): ต้นทุนสินค้าหลักถูกหักตาม % ของ By-Product เช่นกัน และสินค้าที่เป็น By-Product เพียงอย่างเดียวจะได้ราคา = ต้นทุน BoM × % ÷ จำนวน
