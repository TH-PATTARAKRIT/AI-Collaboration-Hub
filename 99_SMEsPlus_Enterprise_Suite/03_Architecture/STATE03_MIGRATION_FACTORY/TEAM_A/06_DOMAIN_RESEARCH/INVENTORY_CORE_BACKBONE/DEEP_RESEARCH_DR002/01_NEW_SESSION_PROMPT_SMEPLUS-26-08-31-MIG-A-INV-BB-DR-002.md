## 7. Research Method — Same Rigor as Accounting

Use the following staged method.

### A0 — Governance / Baseline Verification

Verify:

- governing documents;
- source paths;
- repository path/branch;
- frozen prior evidence commits;
- source version / module landscape relevant to Inventory;
- database/dump availability;
- clean-room/quarantine boundaries;
- unresolved STEP linkage and progress weighting without inventing either.

### A1 — Inventory Source Landscape / Module Universe

Build a focused Inventory source map from the larger source universe.

Classify modules/packages/files into:

- Inventory Core;
- Product/UOM/Location dependency;
- Sales integration;
- Purchase integration;
- Manufacturing integration;
- Accounting/valuation integration;
- Logistics / replenishment / route;
- traceability;
- custom/extra modules;
- source-specific technical/quarantine;
- unknown relevance.

Record exact evidence counts and method. Do not turn source count into SMEsPlus target-module count.

### A2 — Database / Dump Forensics

Where authorized and necessary, inspect schema/data/dump evidence for Inventory facts that source reading alone cannot settle.

Reconcile:

- tables/models/extensions;
- state values;
- field ownership;
- real historical usage;
- source-vs-db contradictions;
- constraints / missing constraints;
- source extension fields;
- migration-invalid states possible via direct SQL.

Every query/result used as evidence must be reproducible and recorded without exposing customer data.

### A3 — Stock Truth / Quantity Semantics

Exhaustively research, where evidenced:

- planned/demand quantity;
- reserved/allocated quantity;
- on-hand quantity;
- available/free quantity;
- executed/moved quantity;
- incoming/outgoing/forecast concepts;
- UOM conversions and precision;
- negative quantity/return semantics;
- partials/backorders;
- over/under fulfillment;
- concurrency or race-sensitive facts;
- derived vs stored facts.

For each concept identify:

`Owner / Lifecycle / Source of Truth / Derived From / Mutation Trigger / Correction Path / Cross-domain Consumer`.

### A4 — Movement / State / Event Lifecycle

Research full lifecycle of:

- receipt;
- delivery;
- internal transfer;
- reservation;
- release/unreserve;
- movement confirmation;
- execution/done;
- cancel;
- return/reversal;
- scrap;
- adjustment;
- backorder;
- correction;
- retry/duplicate implications.

Produce state-transition and event evidence without assuming the vendor state machine should become SMEsPlus design.

### A5 — Warehouse / Location / Product / UOM / Traceability

Research:

- warehouse semantics;
- physical vs logical/virtual locations;
- transit/loss/scrap/customer/vendor/production locations where evidenced;
- multi-warehouse behavior;
- company context;
- branch presence or absence;
- product inventory-management behavior;
- stockable/storable / consumable / service source behavior;
- Product Category relationship;
- UOM and conversion;
- lot/serial;
- expiration where evidenced;
- package/handling unit;
- owner/consignment where evidenced;
- put-away.

### A6 — Route / Procurement / Replenishment

Research:

- routes/rules;
- reorder points;
- replenishment;
- Make-to-Stock;
- Make-to-Order;
- dropship;
- chained movements;
- procurement dispatch;
- source asymmetry between Sales and Purchase;
- duplicate/retry behavior or missing controls.

### A7 — Inventory Adjustment / Physical Count / Cut-off

Research:

- inventory count facts;
- count-in-progress vs settled on-hand;
- adjustment posting triggers at the Inventory side;
- date/effective date behavior;
- period/cutoff interaction evidence;
- historical corrections;
- stock freeze/lock concepts where evidenced;
- audit trail implications.

### A8 — Sales / Purchase / Manufacturing Physical Handoffs

Research E2E handoffs:

- Sale -> Inventory;
- Purchase -> Inventory;
- Manufacturing raw material -> production/WIP -> finished goods;
- returns/cancellation interactions;
- partials;
