## 0. Headline findings (each backed by claims below)

1. **Where valuation is held in 19 (CAP-U10-01).** There is NO stock-valuation-layer model or table. Value lives on `stock.move.value` (stored Monetary, per completed in/out move), unit cost on `product.product.standard_price` and `stock.lot.standard_price` (company-dependent), and manual cost history on `product.value` (product, lot or move scoped). `remaining_qty`, `remaining_value`, `total_value`, `avg_cost` are computed on demand (not stored): FIFO = a stack of `is_in` moves still on hand; AVCO = `standard_price` kept current at each receipt (incremental formula) or replayed from moves; standard = qty × `standard_price`. Claims: C005, C006, C007, C008, C009, C010, C011, C013, C014, C015, C016, C017, C018, C057. **CONTRA flagged**: any earlier-version assumption of `stock.valuation.layer` (remaining quantity/value stored per layer, `quantity_svl`/`value_svl`, a revaluation wizard, stock input/output interim accounts at receipt/delivery) is contradicted by this source.
2. **Perpetual means 'at invoicing' (CAP-U10-02/03).** `inventory_valuation`/`property_valuation` = `periodic` | `real_time` ('Perpetual (at invoicing)'). Real-time entries arise from (a) vendor-bill posting (line account swapped to stock valuation), (b) customer-invoice posting (COGS display_type `cogs` lines), (c) moves to/from locations that carry `valuation_account_id` (inventory loss, production), (d) landed-cost validation. Receipts/deliveries to vendor/customer locations create no stock journal entry in the default configuration. Claims: C104, C105, C106, C107, C108, C111, C120, C121, C123.
3. **`anglo_saxon_accounting` is a different switch.** It is an `account` company Boolean; inside the studied modules it only gates the vendor-bill price-difference lines of `purchase_stock` (standard cost). **CONTRA flagged**: the B01 baseline text calls it the 'perpetual-valuation accounting flag'; in 19 the perpetual selector is `inventory_valuation` (company) / `property_valuation` (category). Claims: C073, C074, C075, C076, C099.
4. **Closing (CAP-U10-04).** Cron `Stock Account: Inventory Valuation Closing` runs daily but processes only companies with `inventory_period` daily/monthly (monthly only on the last day); default is `manual` so the seeded company is never processed. It posts a 'Stock Closing' entry (location reclassification + global stock variation + continental period variation). Claims: C156, C157, C159, C160, C161, C162, C191.
5. **Landed costs (CAP-U10-05)** apply only to FIFO/average products, five split methods, entry only for real-time products and only for quantity still on hand; validated costs cannot be cancelled (negative landed cost instead).
6. **DB state:** 1 company, periodic mode, anglo-saxon off, cost method standard, no stock journal on the company (journal `STJ` exists), 0 moves, 0 quants, 0 storable products, 16 `product_value` rows (service products, dated 0001-01-01), 0 landed costs, no closing parameter. No valuation path was exercised with data.

## CAP-U10-01 Where and how stock value and cost are stored, and the costing methods

**Function-ID(s):** `GRV-F04` (receipt valuation / costing method — used only on claims about valuing receipts); all storage/method claims carry `FUNCTION MAPPING REQUIRED` (no existing ID for 'valuation data model').

**D1 — Business purpose & process semantics.** Give every storable product a unit cost and a total value at any date under one of three methods (standard, FIFO, AVCO), chosen per category with a company default. Receipts are valued from the best available purchase evidence (manual > bill > production > PO price > customer-return origin > product cost); issues are valued at completion from standard price, the running average, or the oldest receipts still on hand. Claims: C025, C026, C027, C030, C034, C035, C036, C039, C040, C041, C042, C062.

**D2 — Architecture / data / object relationships.**
- `stock.move.value` (Monetary, stored, copy=False) — per-move value; `price_unit` is legacy ('To remove and only use value'); `is_in/is_out/is_dropship` stored booleans; `remaining_qty/remaining_value` computed. C005, C008, C009, C010, C011, C021, C022, C024, C045
- `product.product.standard_price` (product module; company-dependent; 'automatically computed in AVCO') and `stock.lot.standard_price` (company-dependent) — unit cost stores. C016, C017, C018, C050, C054, C055, C057
- `product.value` — history of manual changes (product/lot/move). C013, C014, C015
- `product.template.cost_method` / `valuation` computed from `product.category.property_cost_method` / `property_valuation` (company-dependent) else `res.company.cost_method` / `inventory_valuation`; `lot_valuated` on template. C001, C002, C003, C004, C053
- Computed (non-stored): `product.product.total_value`, `avg_cost`, `stock.lot.total_value/avg_cost`, `stock.move.remaining_*`, `stock.quant.value`. C016, C017, C018, C057
- Relationship: valued quantity = `qty_available` under `_with_valuation_context` (valued internal locations; owner none/company; strict). C019, C020, C023, C065

**D3 — Source / technical / workflow logic.**

State (per stock move, valuation-relevant): `draft/confirmed/assigned -> done [action_done]`; `done -> value set [_set_value]`; `done(in) -> value re-derived [bill posted | PO price/qty change | landed cost done | manual product.value | move line qty change]`.

Control flow `_action_done` (override in stock_account): `out moves: _set_value()` (before super, FIFO stack intact) -> `super()._action_done` -> `in/dropship moves: _set_value()` (with `std_price_incremental_recompute` when the batch has no outs) -> `_create_account_move()` -> `outgoing fifo / lot-valuated average: _update_standard_price()` -> `_create_analytic_move()`. C046, C047, C048

Receipt value chain `_get_value_data`: manual product.value -> account (bills; purchase_stock) -> production (mrp_account) -> quotation (PO; purchase_stock) -> returns -> `standard_price`; then `_get_value_from_extra` (landed costs). C039, C040, C041, C042, C043, C044, C064

Per-method rules (effective behavior = stock_account base + purchase_stock/mrp_account/stock_landed_costs overrides when installed):

| Event | standard | average (AVCO) | FIFO |
|---|---|---|---|
| Receipt | in value from evidence chain; `standard_price` NOT changed (`_update_standard_price` skips) | `standard_price` := (prev_qty*old + receipt value)/qty_available, or receipt unit value if prev qty <= 0 | in value from evidence chain; `standard_price` := total_value/qty_available (or last in unit price) |
| Delivery | value = standard_price * qty | value = running standard_price * qty | value from `_run_fifo` over oldest `is_in` moves (partial first move); shortfall at last known price |
| Customer return | in value = original out move value pro-rated (`_get_value_from_returns`) if no bill/PO value | same | same |
| Vendor return | out valued as delivery | out valued as delivery (avg unchanged by an out) | FIFO stack consumption |
| Adjustment (inventory loss/gain) | `standard_price` | `standard_price` (lot price if lot-valuated) | stack / last price |
| Cost update (manual) | write standard_price -> `product.value` history | same (+ lots) | not recorded (derived) |

Claims for the table: C025, C026, C027, C028, C029, C030, C031, C032, C033, C034, C035, C036, C037, C038, C043, C044, C049.
