## Key Flow Summary (L11)

### Payment Registration → Invoice Reconciliation:
1. User invokes `action_create_payments()` on wizard `account.payment.register`
2. `_create_payments()` calls `_init_payments()` → `account.payment.create()`
3. `_post_payments()` → `account.payment.action_post()` → state = `in_process`
4. Each payment's `account.move` has: liquidity line (outstanding account), counterpart line (receivable/payable)
5. `_reconcile_payments()` calls `(payment_lines + invoice_lines).reconcile()` per shared account
6. `reconcile()` → `_reconcile_plan([self])` → creates `account.partial.reconcile` (and `account.full.reconcile` if fully paid)
7. `_compute_payment_state` on invoice recalculates: if residual=0 and all payments matched → `paid`

### Bank Statement Line → Payment Matching → `paid` transition:
1. `account.bank.statement.line.create()` → creates `account.move` with lines: bank account (liquidity) + suspense account
2. Move is auto-posted via `st_lines.move_id.action_post()`
3. Reconciliation wizard/model matches statement line against outstanding payment move line
4. The suspense line on the statement move is replaced with a line on the outstanding account
5. `(st_line_outstanding_line + payment_liquidity_line).reconcile()` → `account.partial.reconcile` created
6. Payment `is_matched` → True; `_compute_state` → payment state transitions to `'paid'`
7. `_compute_payment_state` on invoice: `all_payments_matched = True` → invoice `payment_state = 'paid'`
