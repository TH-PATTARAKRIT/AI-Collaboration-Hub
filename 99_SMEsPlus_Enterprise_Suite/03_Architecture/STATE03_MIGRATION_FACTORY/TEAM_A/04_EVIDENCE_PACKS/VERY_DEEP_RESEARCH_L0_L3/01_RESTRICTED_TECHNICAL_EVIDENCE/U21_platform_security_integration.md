## CAP-U21-01 Second-factor sign-in (authenticator codes and e-mailed codes)

**Function-ID(s):** FUNCTION MAPPING REQUIRED (no entry in the 53-item index covers authentication).

**D1 Business purpose and process semantics.** Optional two-step sign-in. A second variant (module `auth_totp_mail`) sends an e-mailed code to users who have no authenticator when an administrator enforces a policy for employees or for all users VDR-U21-C046 VDR-U21-C048. Administrators can invite users by e-mail VDR-U21-C059 VDR-U21-C061. Passkeys and API keys bypass the step VDR-U21-C092 VDR-U21-C044.

**D2 Architecture / data / object relationships.** `res.users` gains `totp_secret` (varchar column added by `init`, ORM-invisible), `totp_last_counter`, computed `totp_enabled`, `totp_trusted_device_ids` VDR-U21-C017 VDR-U21-C018 VDR-U21-C019. `auth_totp.device` is a model derived from the API-key model with its own table (scope `browser`, hashed key, expiry) VDR-U21-C013. `auth_totp.wizard` (transient) holds the enrolment secret, URL and QR image VDR-U21-C020 VDR-U21-C021. `auth.totp.rate.limit.log` (transient) holds attempt rows VDR-U21-C025 VDR-U21-C027. Mail templates and alert hooks in `auth_totp_mail` VDR-U21-C056 VDR-U21-C057 VDR-U21-C058.

**D3 Source / technical / workflow logic.** `web_login` (web) authenticates the password and, because `_mfa_url()` is not empty, leaves `pre_uid` in the session (core `odoo/http.py:1250-1259`) VDR-U21-C120. POST: `_assert_can_auth` then `_check_credentials({'type': user._mfa_type(), 'token': int})` VDR-U21-C003 VDR-U21-C469; `TOTP.match` accepts counters within one 30 s step either side VDR-U21-C014 VDR-U21-C015 VDR-U21-C016; a counter not greater than `totp_last_counter` is refused VDR-U21-C022 VDR-U21-C023; code checks are rate limited at five per hour per user, cleared on success VDR-U21-C024 VDR-U21-C026.
