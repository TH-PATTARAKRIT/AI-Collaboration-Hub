## CAP-U36-01 Application registry and lifecycle

**Function-ID(s):** `FUNCTION MAPPING REQUIRED`.

**D1 Business purpose and process semantics.** The system is a registry of installable applications. An administrator can refresh the list from disk, schedule an install, upgrade or removal (with dependency closure and compatibility checks), and apply it, after which the system reloads. Removal deletes everything the application owns. Translations of installed applications are loaded for active languages. Operations are tightly restricted to the system administrator role and logged.

**D2 Architecture / data / object relationships.**
- `ir.module.module` (state, dependencies via `ir.module.module.dependency`, exclusions via `ir.module.module.exclusion`, countries, category, auto_install, licence, to_buy, views/reports/menus summary) — C004-C006, C038-C041.
- `ir.module.category` (exclusive flag, privileges link) — C014-C015, C042.

- Config/cron: none specific; test hook refusals — C016-C020, C048.

**D3 Source / technical / workflow logic.**
- `button_install` → `_state_update('to install')` recursive over dependencies (unknown dependency → UserError; external dependency check) → loop adding auto-install modules (`must_install`: all `auto_install_required` deps installed/to install, at least one to install, country filter) unless `skip_auto_install` → exclusion and exclusive-category validation → returns the "Install" action (apply screen) — C007-C015, C042.
- `button_immediate_install/uninstall/upgrade` → `_button_immediate_function`: registry must be ready; no test; `SET LOCAL lock_timeout '3s'`; refuse if any module pending; `LOCK ir_module_module EXCLUSIVE`; `SELECT FROM ir_cron FOR UPDATE`; run scheduling function; commit; `Registry.new(update_module=True)`; commit; rebind request registry; run `next()` (first open `ir.actions.todo` or `/odoo`) or reload client — C016-C020, C048.
- `button_uninstall`: refuses server-wide modules and modules not in installed/to upgrade; marks module and all downstream dependents `to remove`; wizard computes impacted apps and models whose every external id belongs to removed modules — C021-C026, C045-C047, C294-C295.
- `button_upgrade`: `update_list()`, add dependents, base pulls every installed module, newly required dependencies installed — C027-C029.
- `update_list`: manifest scan; updates fields; `_update_from_terp` (dependencies/countries/exclusions/category by SQL) — C032-C035, C051.
- Cancel/reset: `button_reset_state`, wizard `upgrade_module_cancel` — C030-C031, C049-C050.
- State diagram (module):
  - `uninstallable -> uninstalled [update_list sees installable manifest]`
  - `uninstalled -> to install [button_install, dependency closure or auto-install]`
  - `to install -> installed [registry reload with update_module]`
  - `installed -> to upgrade [button_upgrade, includes dependents]`
  - `to upgrade -> installed [registry reload]`
  - `installed -> to remove [button_uninstall, includes downstream dependents]`
  - `to remove -> uninstalled [module_uninstall: data/tables/columns deleted, latest_version cleared]`
  - `to install -> uninstalled; to upgrade|to remove -> installed [button_reset_state or wizard cancel]`
