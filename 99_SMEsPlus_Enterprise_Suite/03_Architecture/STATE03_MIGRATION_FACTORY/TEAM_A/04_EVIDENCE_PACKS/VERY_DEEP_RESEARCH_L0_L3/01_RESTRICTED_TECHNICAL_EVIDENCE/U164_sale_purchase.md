## 4. sale_order_line._purchase_service_generation()

**File:** `sale_purchase/models/sale_order_line.py` lines 295–306

```python
def _purchase_service_generation(self):
    sale_line_purchase_map = {}
    for line in self:
        line = line.with_company(line._purchase_service_get_company())
        # Do not regenerate PO line if the SO line has already created one
        if line.product_id.service_to_purchase and not line.purchase_line_count:
            result = line._purchase_service_create()
            sale_line_purchase_map.update(result)
    return sale_line_purchase_map
```

Guard condition: `service_to_purchase AND purchase_line_count == 0` — idempotent; prevents duplicate PO lines on SO cancel/reconfirm.

## 5. sale_order_line._purchase_service_create()

**File:** `sale_purchase/models/sale_order_line.py` lines 262–293

Core logic:
1. For each SO line, resolves `supplierinfo` via `_purchase_service_match_supplier()` → calls `product_id._select_seller(...)`.
2. Calls `_match_or_create_purchase_order(supplierinfo)`:
   - Searches for an existing draft PO for same partner/company/SO via `_purchase_service_match_purchase_order()`.
   - Searches domain: `partner_id`, `state='draft'`, `company_id`, **and** `sale_order_id = self.order_id.id`.
   - If no match found: creates a new PO via `_create_purchase_order(supplierinfo)`.
3. Appends SO name to PO `origin` field.
4. Creates a PO line via `env['purchase.order.line'].create(values)` where `values` includes `sale_line_id: self.id` — this is the hard foreign-key link.
5. Returns `sale_line_purchase_map`: `{SaleOrderLine → PurchaseOrderLine recordset}`.

```python
@api.depends('purchase_line_ids')
def _compute_purchase_count(self):
    database_data = self.env['purchase.order.line'].sudo()._read_group(
        [('sale_line_id', 'in', self.ids)], ['sale_line_id'], ['__count'])
    mapped_data = {sale_line.id: count for sale_line, count in database_data}
    for line in self:
        line.purchase_line_count = mapped_data.get(line.id, 0)
```

Efficient batched `_read_group` count; used both in gate condition and as stat display.

## 11. Quantity Increase — Additional PO Line or Qty Update

**File:** `sale_purchase/models/sale_order_line.py` lines 99–112

```python
def _purchase_increase_ordered_qty(self, new_qty, origin_values):
    for line in self:
        last_purchase_line = self.env['purchase.order.line'].search(
            [('sale_line_id', '=', line.id)], order='create_date DESC', limit=1)
        if last_purchase_line.state in ['draft', 'sent', 'to approve']:
            quantity = line.product_uom_id._compute_quantity(new_qty, last_purchase_line.product_uom_id)
            last_purchase_line.write({'product_qty': quantity})
        elif last_purchase_line.state in ['purchase', 'cancel']:
            quantity = new_qty - origin_values.get(line.id, 0.0)
            line._purchase_service_create(quantity=quantity)
```

- Draft PO: updates existing PO line quantity.
- Confirmed/cancelled PO: creates a new PO line for the delta quantity.

## 14. PO Delivery Address Propagation

```python
@api.depends('order_line.sale_order_id.partner_shipping_id')
def _compute_dest_address_id(self):
    super()._compute_dest_address_id()
    for po in self:
        if not po._should_set_dest_address():
            continue
        sale_orders = po._get_sale_orders()
        if len(sale_orders.partner_shipping_id) == 1:
            po.dest_address_id = sale_orders.partner_shipping_id
```

When all linked SOs have a single common shipping address, the PO inherits it as `dest_address_id`. Only if `_should_set_dest_address()` is True (requires `dest_address_id` already set).

## 17. PO Order Values Construction

**File:** `sale_purchase/models/sale_order_line.py` lines 122–141

`_purchase_service_prepare_order_values(supplierinfo)` builds the PO header dict:
- `partner_id`: from supplierinfo
- `company_id`: from `_purchase_service_get_company()`
- `currency_id`: supplier property or company default
- `dest_address_id`: False (stock not involved in base module)
- `origin`: SO name
- `date_order`: commitment_date minus supplier delay (`relativedelta(days=int(supplierinfo.delay))`)
- `fiscal_position_id`: auto-computed via `account.fiscal.position._get_fiscal_position`

## 18. PO Line Values Construction

**File:** `sale_purchase/models/sale_order_line.py` lines 174–220

`_purchase_service_prepare_line_values(purchase_order, quantity=False)` builds PO line dict:
- `product_qty`: converted from SO UoM to product UoM or supplier UoM
- `sale_line_id`: `self.id` — the explicit back-link to SO line
- `date_planned`: `purchase_order.date_order + relativedelta(days=int(supplierinfo.delay))`
- `price_unit`: from supplierinfo, with tax exclusion fix and currency conversion
- `analytic_distribution`: copied from SO line if present
- `discount`: from supplierinfo
