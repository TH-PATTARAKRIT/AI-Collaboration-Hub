## Summary

### Segment 1 — SO Confirm (U76-001 to U76-009)
- `action_confirm` → `_prepare_confirmation_values` → state `draft/sent → sale`
- `sale_stock._action_confirm` calls `order_line._action_launch_stock_rule()` → `stock.rule.run(procurements)` → creates `stock.picking` (delivery order) via pull route rules
- NO `account.move` created at SO confirm step

### Segment 2 — Delivery Validate (U76-010 to U76-024)
- `button_validate` → `_action_done` (picking) → `todo_moves._action_done` → `stock_account._action_done`
- `stock_account._action_done`: freeze out-move values, call `super()`, compute in-move values, call `_create_account_move()`
- `_create_account_move` creates ONE `account.move` per batch using `company_id.account_stock_journal_id`; immediately posts via `_post()`
- For outgoing delivery (internal → customer): DR = customer-location `valuation_account_id` (COGS/Expense account) / CR = `product.categ_id.property_stock_valuation_account_id` (Stock Valuation)
- This is identical for standard-cost and AVCO; only the monetary `value` differs (AVCO uses running average unit cost)
- The `account.move.ref` is built from the stock move `reference` field (delivery order name)

### Segment 3 — Invoice Create and Post (U76-025 to U76-033)
- `_create_invoices` → `_prepare_invoice` (move_type='out_invoice', journal_id from SO or default sale journal) → `_create_account_invoices` (sudo create)
- Invoice lines: revenue account from `product_tmpl_id.get_product_accounts()['income']`; receivable line from `partner_id.property_account_receivable_id`
- `action_post` → `_post(soft=False)` → state `draft → posted`; tax lines added by `_compute_tax_line_ids` during line compute

### Segment 4 — Payment Register (U76-034 to U76-043)
- `account.payment.register` wizard → `action_create_payments` → `_create_payments` → `_init_payments` + `_post_payments` + `_reconcile_payments`
- Payment `account.move` entry (inbound): DR `payment_method_line.payment_account_id` (outstanding receipts) / CR `partner.property_account_receivable_id` (receivable)
- Bank account determined by the journal's `payment_method_line_id.payment_account_id`

### Segment 5 — Reconcile (U76-035 to U76-048)
- `_reconcile_payments` auto-reconciles payment lines against invoice receivable lines on the same account
- Calls `(payment_lines + invoice_lines).reconcile()` → `_reconcile_plan` → `_reconcile_plan_with_sync`
- Full reconciliation creates `account.full.reconcile` record; all participating lines get `full_reconcile_id` set
- After reconciliation: `invoice.line_ids.filtered(receivable).reconciled = True`, `amount_residual = 0.0`
- Invoice `payment_state` transitions to `'paid'` when `amount_residual == 0`

### Cross-chain state machine (U76-049 to U76-050)
- `delivery_status='full'` when all pickings done/cancel (sale_stock computed field)
- `invoice_status='invoiced'` when all SO lines fully invoiced (sale computed field)
- No single method checks the full O2C completion; the three fields (`state='sale'`, `delivery_status='full'`, `invoice_status='invoiced'`) are independently computed
