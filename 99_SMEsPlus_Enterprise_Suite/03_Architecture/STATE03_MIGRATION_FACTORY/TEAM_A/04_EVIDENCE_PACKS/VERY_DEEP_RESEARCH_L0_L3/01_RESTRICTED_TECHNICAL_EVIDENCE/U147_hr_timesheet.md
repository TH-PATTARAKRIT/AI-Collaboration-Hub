## Key Architectural Findings

1. **Timesheets ARE analytic lines** — The `account.analytic.line` table stores both generic analytic costs and timesheet entries. The discriminator is `project_id IS NOT NULL`. No separate table or model name exists for timesheets.

2. **Cost computed, not journalized** — `hr_timesheet` computes a monetary `amount` = `-(unit_amount × hourly_cost)` and stores it on the analytic line. No `account.move` (journal entry) is created by this module. Accounting entries only appear if `sale_timesheet` is installed and the timesheet is invoiced.

3. **Analytic account mandatory for timesheet projects** — The project model enforces that `allow_timesheets=True` requires a non-null `account_id`. Auto-creation of analytic accounts occurs on project create if none is supplied.

4. **Three-tier security** — `group_hr_timesheet_user` (own records), `group_hr_timesheet_approver` (all), `group_timesheet_manager` (admin + HR). Portal access exists but is disabled by default and toggled via the project collaborator mechanism.

5. **No core cron** — Reminder flags exist in settings but no scheduled action is defined in the community module.
