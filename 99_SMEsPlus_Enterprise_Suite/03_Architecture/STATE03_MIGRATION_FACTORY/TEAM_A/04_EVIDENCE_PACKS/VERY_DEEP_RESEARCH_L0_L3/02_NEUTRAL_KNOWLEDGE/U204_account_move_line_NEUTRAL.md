## Key Migration Flags Summary

1. **REMOVED: analytic_account_id** — field does not exist on `account.move.line` in v19. Any migration script from v16 or earlier that writes this field will fail silently or raise an error.

2. **REMOVED: analytic_tag_ids** — M2M field does not exist on `account.move.line` in v19. Analytic tags as a separate concept no longer apply to journal items.

3. **ADDED: analytic_distribution** — JSON field replaces both removed fields. Keys are comma-separated analytic account IDs; values are percentages. Migration must transform old single-account FK and tag M2M into this JSON structure.

4. **balance is primary** — In v19, `balance` is the stored master field; `debit` and `credit` are computed. Any migration that writes `debit`/`credit` directly uses the inverse setter which sets `balance`. Prefer writing `balance` directly for bulk migrations.

5. **tax_line_id is derived** — Do not attempt to set `tax_line_id` directly; set `tax_repartition_line_id` instead.

6. **move_type is non-stored** — Any query filtering `account_move_line.move_type` will join to `account_move`. Use `move_id.move_type` in domain expressions.
