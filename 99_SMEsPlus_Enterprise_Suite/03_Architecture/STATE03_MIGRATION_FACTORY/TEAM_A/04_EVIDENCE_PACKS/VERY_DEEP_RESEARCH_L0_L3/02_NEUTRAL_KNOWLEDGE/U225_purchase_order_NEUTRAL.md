## Key Migration Signals

1. **Analytic architecture change**: The single-account analytic link on purchase lines is gone. Migration tooling must convert any stored single-account references into the JSON distribution format.

2. **Receipt status module boundary**: Any SMEsPlus customization that reads receipt status must have `purchase_stock` installed. The base `purchase` module has no such field.

3. **No Done state**: The purchase order status never reaches a terminal "Done" value in v19 Community. Downstream integrations checking for a "done" state will fail silently.

4. **Billing status precondition**: The `invoice_status` field only returns meaningful values when the order is in Purchase Order status. Pre-confirmation checks on billing status are always "Nothing to Bill" regardless of actual bill activity.

5. **Date semantics**: Three distinct dates exist — order deadline, confirmation timestamp, and arrival date — each from a different module layer. The arrival date requires `purchase_stock`.
