## Summary of Key Architectural Patterns

1. **Unified module** — all eCommerce loyalty types (coupons, promotions, gift cards, eWallet, loyalty cards) handled in one module.
2. **Session-based state** — error and success messages stored in `request.session` and read-once by QWeb, not in URL parameters (except the share-link flow).
3. **Deferred code application** — pending_coupon_code session key allows codes to survive until a cart is created.
4. **Reward recalculation on every cart event** — `_update_programs_and_rewards()` called on cart load, line update, delivery change, and before payment.
5. **Payment guard** — final reward validation with amount comparison at transaction time prevents payment of stale amounts.
6. **No POS coupling** — eCommerce loyalty operates independently from POS loyalty; shared base is `sale_loyalty` / `loyalty` core models only.
