## Key Integration Points for Migration

1. **Won status is derived** — migrating `won_status` directly is wrong; migrate `active`, `probability`, and `stage_id.is_won` correctly and the status recomputes.
2. **PLS frequency table** must be rebuilt from historical data post-migration; without it, all new leads get a default probability.
3. **`date_closed`** is set by write-time logic; importing it as a raw value bypasses the logic and may produce inconsistencies if `probability` or `active` do not match.
4. **Email aliases** require alias domain configuration in the target environment.
5. **System parameter `crm.lead.auto.assignment`** controls assignment mode; must be explicitly set post-migration.
6. **Team `company_id`** scoping: leads in a multi-company setup inherit company from team; incorrect mapping causes company mismatch errors.
