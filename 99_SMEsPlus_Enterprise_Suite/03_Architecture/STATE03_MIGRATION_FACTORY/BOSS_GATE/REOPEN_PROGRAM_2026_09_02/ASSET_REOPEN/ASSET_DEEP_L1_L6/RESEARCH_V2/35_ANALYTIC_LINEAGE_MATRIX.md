# 35 — ANALYTIC LINEAGE MATRIX
**LAYER 2 — AUDIT QUARANTINE**

Required matrix J (§82).

## 1. The asset lineage

| # | Step | Mechanism | Timing | Reversible? |
|---|---|---|---|---|
| 1 | Vendor bill line carries a distribution | Manual or defaulted at AP coding | At bill entry | Yes, before posting |
| 2 | → asset distribution | **Balance-weighted** across all source lines | At asset creation | Yes — the field is editable |
| 3 | Template default | Used **only when the bill supplies none** | At template selection | Yes |
| 4 | → depreciation entry | Copied **at entry preparation**, onto **both** lines | Each time an entry is prepared | Only by editing the posted entry |
| 5 | → analytic lines | Generated by the accounting layer | On posting | Via the entry |
| 6 | → analytic reporting | Aggregation | On read | — |

**Every arrow is a copy at a moment in time.** No arrow is a live reference.

## 2. The production lineage — for comparison

| # | Step | Mechanism |
|---|---|---|
| 1 | Work centre carries a distribution | Manual configuration |
| 2 | → work-order analytic lines | Generated from the **work centre's** distribution, value = `−hours × rate`, unit = hours, category *manufacturing order* |
| 3 | Rewritten whenever duration changes | Existing lines updated in place |
| 4 | Deleted on cancel | |

## 3. Where the two lineages meet

**In the analytic ledger, and nowhere else.**

Depreciation arrives tagged with the **asset's** distribution, inherited from a
supplier invoice. Machine time arrives tagged with the **work centre's**
distribution, configured by hand. If both point at the same analytic account, both
costs land there — with no relationship, no reconciliation, and nothing preventing
the same economic cost being represented twice.

`FACT VERIFIED`

**This is simultaneously the cheapest opportunity and the clearest trap.** It is the
one place the two truths already coexist, so it is where a costing concept can be
proven before any structural change. It is also where double-counting will happen
first if the design is careless.

## 4. Change behaviour

| Change | Historical entries | Future entries | Reported anywhere? |
|---|---|---|---|
| Asset distribution changed | **Unchanged** | New distribution | **No** |
| Work centre distribution changed | Existing analytic lines unchanged | New work orders only | **No** |
| Analytic account archived | Historical lines remain | Not blocked by the asset | **No** |
| Analytic account company changed | Not checked by the asset | Not checked | **No** |
| Distribution ≠ 100% | Not validated at the asset | Not validated | **No** |

Five change paths, **zero reports**. `FAIL-A02`…`FAIL-A08`, `UNR-11`.

## 5. Consequences

1. **Depreciation analytic quality is determined by accounts-payable coding.** The
   distribution is inherited from the supplier invoice. That is an operational
   control, not a system feature.
2. **Analytic appears on both sides of the depreciation entry** — expense and
   accumulated depreciation. Any consumer must filter by account type or it will
   double-count.
3. **Analytic records attribution; it does not allocate.** It is a tag. The logic
   that decides how much cost goes where is upstream, and it does not exist
   (`21` §9).
