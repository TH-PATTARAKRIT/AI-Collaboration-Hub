## 4. PMO FINDINGS ON THE SESSION'S OWN CONDUCT

**PMO-01 — The author's denominator was wrong twice, and both times a reviewer caught it.** An author-chosen 13-module producer list against a measured 9-module set with 5 members absent from the list; and a population stated in the wrong unit. **The denominator rule has now caught an author defect in every round it has been applied to.** PMO records that the rule's value is not diminishing with familiarity.

**PMO-02 — The brief-error clause fired twice and should be treated as standard, not optional.** One brief carried a wrong path; another was missing roots and the reviewer correctly declared class C rather than substituting. Both were returned as findings because the clause required it.

**PMO-03 — The most valuable single result of the session is a disproof, not a confirmation.** One of the author's own candidates was disproved by an independent enumeration of callers. PMO records this as the intended outcome of adversarial review and notes that a challenge phase producing only confirmations should be regarded as under-powered.

**PMO-04 — The constitution correction was absorbed without loss.** No evidence was discarded, no completed work repeated, no research re-run. Only the interpretation layer changed, and the superseded wording is retained verbatim so the over-constraint stays legible.

**PMO-05 — Severity ranking changed after synthesis.** The finding ranked first by AAS+ (schema-altering rights reachable by every internal user through one settings toggle) could not be ranked first by any individual reviewer, because it requires holding the destructive-lifecycle findings and the access findings together. **PMO records that per-expert severity is not additive and that the synthesis step is load-bearing, not ceremonial.**

**PMO-06 — Nothing in this package was executed.** No database, no runtime, no deployment. Every operational consequence is a code-path conclusion, explicitly hedged. **PMO regards this as the principal limitation of the package** and notes that four dependencies (`DEP-P09-05`, `-06`, and the operational halves of CH-CAND-02/03/04) can only be closed by execution.
