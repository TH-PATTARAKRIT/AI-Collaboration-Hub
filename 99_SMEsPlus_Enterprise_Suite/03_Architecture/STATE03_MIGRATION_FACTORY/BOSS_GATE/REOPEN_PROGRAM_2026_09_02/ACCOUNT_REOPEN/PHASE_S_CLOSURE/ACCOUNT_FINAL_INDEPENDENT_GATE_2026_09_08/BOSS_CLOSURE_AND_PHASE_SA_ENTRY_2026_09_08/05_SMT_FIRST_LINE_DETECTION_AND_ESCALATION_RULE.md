# SMT FIRST-LINE DETECTION & ESCALATION RULE

Authority: Boss — Sole Final Approver  
Applies to: Account Phase SA and any later SMEsPlus functional design continuation unless superseded by an explicit Boss ruling.

## 1. Core rule

**Boss must never be the first detector of a material functional, clean-room, evidence, architecture, control, audit, SaaS-boundary, or source-copying defect.**

The first-line detection responsibility belongs to the relevant **SMT functional/domain team** and its associated architecture/audit reviewers.

If a defect reaches Boss only because SMT failed to identify, challenge, classify, or contain it first, that is a governance/process failure and must be recorded as such.

## 2. What SMT must detect before Boss review

Before any function is presented to Boss, SMT must explicitly test for:

1. Business semantic ambiguity.
2. Missing or weak evidence.
3. Reference-system behavior being copied without independent SMEsPlus rationale.
4. Vendor schema / ORM / state / workflow / UI being treated as design authority.
5. Missing Clean-room justification.
6. Missing SMEsPlus Nature DNA.
7. Tenant or Company isolation weakness.
8. Accounting ownership / event / posting ambiguity.
9. Control, approval, audit-trail, reversal, correction or immutability weakness.
10. Cross-module contradiction or hidden dependency.
11. Version/source-generation overclaim.
12. A design that cannot state what SMEsPlus does better or differently.
13. A function that requires targeted Very Deep Research before design can be trusted.

## 3. Mandatory SMT pre-Boss gate

Every material function must pass the following sequence before reaching Boss:

`SMT FUNCTION OWNER REVIEW`
-> `SMT CLEAN-ROOM CHALLENGE`
-> `SMT CROSS-DOMAIN / CONTROL CHECK`
-> `SMT MATERIALITY CLASSIFICATION`
-> `TARGETED VERY DEEP RESEARCH IF REQUIRED`
-> `SMT RE-CHALLENGE`
-> `BOSS PACK ONLY IF BOSS AUTHORITY IS ACTUALLY REQUIRED`

SMT may not route a basic uncertainty, incomplete analysis, untested assumption, or source-copying question directly to Boss.

## 4. When Boss escalation is allowed

Escalation to Boss is allowed only when SMT has completed the applicable analysis and one of the following remains:

- a genuine policy/constitutional decision reserved to Boss;
- two or more defensible alternatives with material business consequences;
- a cross-domain architecture conflict that cannot be resolved within approved rules;
- a statutory/security/risk position that requires Boss acceptance after expert analysis;
- a material exception to an existing Boss-approved constitution;
- a material unresolved issue after targeted Very Deep Research and independent challenge;
- final approval/freeze authorization.

## 5. Boss pack quality rule

A Boss escalation must never be a raw question. It must include:

- exact issue;
- evidence;
- why SMT could not resolve it under existing authority;
- alternatives;
- impact/risk;
- SMT recommendation;
- dissent/challenge result, if any;
- exact decision requested from Boss.

If SMT cannot provide this pack, the item is **NOT READY FOR BOSS**.

## 6. Very Deep Research re-entry ownership

SMT, not Boss, is responsible for detecting the need for targeted Very Deep Research during normal execution.

When triggered:

- freeze the affected function;
- preserve prior learning and Boss rulings;
- reopen only the material unknown;
- research to the depth necessary to remove or defensibly bound the uncertainty;
- re-synthesize under Clean Room 100%;
- re-challenge before returning to the Phase SA stream.

Boss retains the right to order Very Deep Research at any time, but normal quality control must not depend on Boss being the first person to notice the problem.

## 7. Accountability

A function reaching Boss with an obvious unresolved Clean-room defect, unsupported assumption, unchallenged source dependency, or material functional ambiguity is treated as an **SMT escape**.

Every SMT escape must produce:

- escape record;
- root cause;
- missed control;
- correction;
- prevention rule;
- re-challenge result.

The purpose is not punishment; the purpose is to prevent Boss from becoming the project's first-line QA detector.

## 8. Standing principle

> **SMT detects first. SMT challenges first. SMT researches first. SMT recommends first. Boss decides only what truly requires Boss authority.**

No Evidence = No Progress. Never Skip Gate. Boss remains the sole Final Approver.
