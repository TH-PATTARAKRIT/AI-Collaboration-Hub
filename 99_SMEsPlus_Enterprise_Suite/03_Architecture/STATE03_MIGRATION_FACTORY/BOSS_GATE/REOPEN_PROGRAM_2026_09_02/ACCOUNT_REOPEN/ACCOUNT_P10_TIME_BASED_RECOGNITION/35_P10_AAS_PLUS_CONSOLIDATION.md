## 3. What AAS+ Now Holds

### 3.1 On the design question

The kernel case is **narrower than the parent round claimed and wider than the reconciliation round claimed.** Both errors were made in the same session.

- The parent round claimed six kernel elements. Two of the three decisive arguments belonged to another process. **Too wide.**
- The reconciliation round then narrowed to two, and in doing so handed away the attribution defect — which is *not* a posting-layer property but **two independent mechanism-level implementations of the same wrong shape**. That is the single best evidence for a shared allocation layer in the entire package. **Too narrow.**

**AAS+ position: three elements.**

> A thin shared recognition layer owning **(1) the allocation convention library, (2) the correction algebra, and (3) the attribution construction** — specialising the accounting-event object once it exists — with separate domain engines owning objects, lifecycles, posting patterns and business rules.

Element 3 is restored on evidence produced by challenge, against P10's own earlier judgement.

### 3.2 On the event identity

AAS+ **upholds** the withdrawal of a P10-authored identity, and **adds the instrument P10 failed to issue.**

The withdrawal was correct in substance and unsound in evidence: it rested on a peer negative P10's own intake rule required it to treat as unverified. P10 has since verified the narrower form — no accounting-event object **within the reference root**, class `A`, one root — which supports *"do not author a competing identity here"* without supporting the peer's universal claim.

But P10 gave away the object **and** kept no instrument. Of the three processes blocked on it, P10 was the only one holding nothing.

> **`AASP-COND-01`** — P10's acceptance of the accounting-event object authored under `D-5` is **conditional** on that object satisfying: the anchor grades P10 has verified (line-level, object-plus-period, move-set, none); a **period carried independently of the posting date**; and the exclusion of point-in-time estimates from the recognition abstraction. If `D-5` is taken without them, P10 will have lost the object and the specification.
