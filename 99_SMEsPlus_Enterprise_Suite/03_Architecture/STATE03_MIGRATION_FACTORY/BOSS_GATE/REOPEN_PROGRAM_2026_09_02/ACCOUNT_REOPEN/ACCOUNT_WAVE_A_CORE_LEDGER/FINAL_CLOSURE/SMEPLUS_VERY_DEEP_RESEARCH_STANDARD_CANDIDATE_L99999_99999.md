## 2. The rules

### `ER-CORE-1` — Denominator-first research

> **Nothing is counted until `POPULATION` + `PATTERN` + `PATH SET` + `UNIT` are declared, and none may
> be author-chosen.**

*Earned:* two disciplined enumerations of one bounded surface returned **12** and **14**. Neither was
wrong. **The unit was never defined.**

*Test:* can a second reviewer reproduce the count from the declaration alone, without asking a
question? If not, the denominator is not declared.

### `ER-CORE-2` — Full manifested-tree enumeration, **proved at the ROOT level**

> **Declare the pattern AND prove the path set — and the proof of a path set is an enumeration of the
> ROOT SET, not of one root.**

*Earned twice, one level apart:*
- `MCC`: the source root held a **second module tree of 961 directories** that no round had searched.
  Rule became *"prove the path set."*
- **`FC`: the ROOT SET itself was never enumerated. `1` root of `22`. `1,753` manifested modules of
  `23,530`.** The correction had moved the defect **up one level**, not removed it.

*Test:* name the discovery pattern that produced your root set (e.g. *"every directory containing
`addons/base/models/res_currency.py`"*), and state its blind spot. **If you cannot name the pattern,
you do not have a root set — you have a habit.**

### `ER-CORE-3` — Correction propagation by **mechanism**, not intention

> **A single governing register that every consumer resolves against — and the register must be checked
> against itself before publication.**

*Earned four times:*
1. No channel existed (`MCU-17`).
2. `J-16` — a closure propagated to 2 files of 5, **in the round that specified the rule, hours after
   specifying it**.
3. **`FC-F1` — `MCC_00`, the mechanism built to end (1) and (2), shipped with its §1 count
   contradicting its own §2 dispositions. No consumer noticed.**
4. `V-SYS-2` — an independent sibling session consumed a parent's findings but not its **corrections**.

*Test:* recompute every published count from the register's own disposition rows. **They must agree.**

### `ER-CORE-4` — An empty class means `UNSEARCHED`, never `ABSENT`

*Earned:* both taxonomy classes standing at zero produced a **verified defect on first search**
(`MCU-14` → `BW-30`; `MCU-15` → `BW-35`). **A 2-of-2 record.**

*Corollary:* a class with **one** member is a **hypothesis**, not a class. Record it so the next round
searches it. (Applied to `executed-and-wrong` in this round.)

### `ER-CORE-5` — Cross-version source divergence review

> **A behavioural change with no schema change leaves NO migration artefact. A DDL-shaped migration
> gate cannot see it.**

*Earned:* `GB-08`. One three-line diff changes which company's rate values every transaction, in
**5 of 22** roots, with no schema change anywhere.

*Test:* for every load-bearing semantic, diff it across the **declared root set** — not two trees.

### `ER-CORE-6` — Negative-claim boundedness

> **`NO EVIDENCE FOUND` ≠ `DOES NOT EXIST`.** Classes `A`–`E`. **A class `A` claim must state the path
> set it is complete over, and quantify what it excludes.**

*Earned:* every class `A` absence in Wave A's history is scoped to ≤1 root of 22 and **none said so** —
which makes it class `E` wearing class `A`'s label.

*Test, added by this round:* **state the bound as a fraction.** *"6 roots of 22"* is compliant.
*"the source tree"* is not.

### `ER-CORE-7` — Reviewer claim verification

> **Reviewers verify CLAIMS against SOURCE. A reviewer who reviews prose finds prose defects.**

*Earned:* the strongest findings of every round came from reviewers who re-derived a claim from source
and found the mechanism did not exist as described (`FX-08`'s writer half; `J-11`; `FC-C1`/`FC-C2`).

*Counter-rule earned in the same place:* **a reviewer's finding is a claim too.** This round confirmed
5 of 6 re-tested reviewer findings exactly and corrected 1.

### `ER-CORE-8` — Hash the package **before** review

> Every reviewer verdict names the digest it reviewed.

*Earned:* the `MCC` audit panel recorded that the package **changed while it was under review**.

### `ER-CORE-9` — Fixed-point convergence

> **Convergence = two consecutive INDEPENDENT passes returning no material delta.**
> A stable **recommendation** is not convergence. Five passes reaching `HOLD` while still finding new
> material is evidence of the recommendation, not of convergence.

*Test:* is the **rate of new findings** decaying? Wave A: `MC` → `MCC` → `FC` each returned material new
findings on first contact. **Not decaying.**

### `ER-CORE-10` — Publication sequencing

> **Order: verify local → push → re-read from origin → verify link → verify SHA + digest → then Jira.**
> **Never post a link to an unpushed branch.** If push is blocked, declare
> `GITHUB EVIDENCE PUBLICATION NOT VERIFIED` and fabricate nothing.

*Earned:* the `MCC` round's push was refused; it **correctly withheld** the Jira comment rather than
cite a dead branch. **That is the standard's best-executed rule to date.**

*Extension earned by this round:* **verify branch state against `origin`, not against the local branch.**
`MCC_L` reported its prompt *"NOT COMMITTED"* from a `git log` over **its own branch**; the prompt was
committed on a **sibling** branch on `origin` (`FC-F5`). **A bounded search reported as an unbounded
absence — `ER-CORE-6` appearing in a governance claim, where nobody was looking for it.**

### `ER-CORE-11` — Boss-decision isolation

> **Research closes MECHANISMS. Boss decides POLICY. Never route one into the other.**

*Two symmetrical abuses, both observed:*
- **Forward:** routing an open blocker to a later Wave to clear a Gate. *(Re-tested every round; clean.)*
- **Backward, and it is the subtler one:** holding a **determined mechanism** open as an "unknown"
  because its **consequence** is policy-dependent. **`MCU-04` sat in that state through two gate
  reports.** It inflates the unknown count exactly as forward routing deflates it.

*Test:* is the **mechanism** determined by source? If yes, the unknown is **closed** — and what remains
is a **decision about a known defect**, which belongs in the decision register, not the unknown register.

### `ER-CORE-12` — Panel liveness

> **No finding may be marked complete while a panel is still running, and liveness is tested
> MECHANICALLY, not assumed.**

*Earned:* this round found a sibling panel actively writing (20 files in 4 minutes, a veto report
appearing mid-session). Had it assumed completion, it would have declared closure over a running
independent review.

*Test:* `find <package> -mmin -N`. Not a status line — a filesystem check.

## 3. What this standard has NOT yet demonstrated

Stated, because a standard that hides its own record is the failure it names:

| Claim a canonical standard would need | Status |
|---|---|
| It converges | **NOT DEMONSTRATED.** Three rounds, no decay in new findings |
| It bounds its own search | **NOT DEMONSTRATED** — `ER-CORE-2` failed at the root level in the round that wrote it |

| It is transferable to other modules | **PARTIALLY** — `ER-CORE-1` transferred to Inventory unchanged |
| Its findings reproduce | **DEMONSTRATED** — 5 of 6 exact, and one parent count reproduced to the digit |

> **Two of its twelve rules have failed inside the rounds that authored them.** That is why this is a
> `CANDIDATE`.
>
> **It is also the strongest argument for it:** a method that catches its own rules failing, names the
> round responsible, and publishes the count that proves it, is doing the one thing a research standard
> exists to do.
