# P01 — ACCOUNTING EVENT REGISTER

Session: `SMEPLUS-26-09-04-ACC-P01-P2P-REV2-001`
Layer: **1 — Clean-room business learning.**

An accounting event is recorded here only where evidence shows a journal effect is actually
produced. Where an event is conditional, the condition is stated as part of the event.

| ID | Accounting event | Trigger | Condition for existence | Class |
|---|---|---|---|---|
| `AE-P01-01` | Inventory recognised on receipt | Goods receipt completion | Item storable **and** continuous valuation | FACT VERIFIED `EV-P01-04`,`EV-P01-05` |
| `AE-P01-02` | Goods-received clearing obligation raised | Same event as `AE-P01-01` | Same | FACT VERIFIED `EV-P01-07` |
| `AE-P01-03` | Order-stage accrual raised | Manual invocation of the accrual routine against an order | Operator action; no automatic trigger found | FACT VERIFIED `EV-P01-16` |
| `AE-P01-04` | Order-stage accrual reversed | Automatic, at the reversal date supplied when the accrual was raised | Always paired with `AE-P01-03` in the observed code path | FACT VERIFIED `EV-P01-16` |
| `AE-P01-05` | Payable recognised | Vendor bill posting | Unconditional — every purchase shape reaches it | FACT VERIFIED |
| `AE-P01-06` | Clearing obligation discharged | Vendor bill posting | Item storable **and** continuous valuation **and** clearing model on | FACT VERIFIED `EV-P01-09` |
| `AE-P01-07` | Expense recognised directly | Vendor bill posting | Item **not** storable, **or** periodic valuation | FACT VERIFIED |

## The events that are NOT produced

Recorded explicitly, each with a class letter and a scope, because their absence is
architecturally load-bearing.

| Non-event | Scope of the search | Class |
|---|---|---|
| No accounting event at order confirmation | `R1`, the order model's confirm and approve paths | **A** within that scope |
| No accounting event at receipt for a consumable item | `R1`, the valuation entry routine's own guard | **A** within that scope |
| No accounting event at receipt for a periodically-valued item | `R1`, the valuation-layer posting guard | **A** within that scope |
| No receipt document at all for a service purchase | `R1`, derived from the receipt-side guards | **B** — the absence of a *document* was inferred from the absence of a valuation path, not searched for directly |
| No year-end / period-close entry generated by P01 | not searched in this session | **C** |
| No price-difference posting where the item lacks an expense account | `R1`, the price-difference routine | **A** within that scope |

**No class B, C or D entry in this table may be restated elsewhere as a class A verified
absence.**
