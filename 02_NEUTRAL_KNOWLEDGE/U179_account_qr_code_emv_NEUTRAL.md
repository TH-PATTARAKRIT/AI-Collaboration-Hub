# U179 Neutral Reference — account_qr_code_emv (Thai PromptPay / EMV QR Code on Invoices)

| Neutral-ID | Neutral reference |
|---|---|
| N-U179-01 | The bridge module ships a constants file, a single model extension file, and a bank-account form view extension, plus an internationalization directory with locale files for 47 languages. The module depends only on the core accounting module. |
| N-U179-02 | The module extends the bank-account model to add a QR-settings visibility flag, a reference-inclusion toggle, a proxy-type selector, a computed list of allowed proxy keys for the current country, and a proxy value field. |
| N-U179-03 | Each data object in the EMV payload is serialized as a two-digit tag identifier, a two-digit length value, and the data value itself — a format defined by the EMV Merchant-Presented QR Code specification. Absent or empty values are omitted from the payload. |
| N-U179-04 | A compliant EMV QR payload for payment contains: a payload format indicator, a point-of-initiation method marker, a merchant account information block, a merchant category code, a transaction currency code, an optional transaction amount, a country code, a merchant name, a merchant city, and an optional additional data field for payment references. |
| N-U179-05 | The EMV specification mandates a CRC-16 integrity check appended at the end of every QR string. The checksum covers all data including the four-character CRC tag and length prefix, and is expressed as four uppercase hexadecimal digits. |
| N-U179-06 | The merchant name embedded in the QR code is limited to 25 characters per EMV spec; the merchant city is limited to 15 characters. Both fields are transliterated to remove diacritics before encoding. |
| N-U179-07 | The transaction currency is encoded in tag 53 as a three-digit ISO 4217 numeric code. Thai Baht is code 764. The code is resolved dynamically from the invoice currency, not hardcoded; a lookup table maps alphabetic codes to numeric equivalents. |
| N-U179-08 | The transaction amount in tag 54 is omitted for zero-value QR codes (allowing any amount to be entered by the payer). For non-zero amounts, the value is encoded without trailing decimals when it is a whole number. |
| N-U179-09 | The Thai PromptPay merchant account block occupies tag 29 and contains the PromptPay application identifier followed by a sub-tag whose number encodes the proxy type (mobile phone, tax ID, or e-wallet) and whose value carries the proxy address. Mobile numbers are converted from local format to international format before encoding. |
| N-U179-10 | Thai bank accounts support three proxy types for PromptPay: mobile phone number (10 digits in local format), merchant tax identification number (13 digits), and e-wallet identifier. Validation rules specific to each format are enforced at the data layer. |
| N-U179-11 | EMV QR code generation for Thai bank accounts is restricted to invoices denominated in Thai Baht. Attempting to generate a QR code on a Thai bank account invoice using any other currency raises an error before rendering. |
| N-U179-12 | The QR image delivered in the invoice PDF is produced by the reporting engine's barcode renderer, configured for QR type at 128 × 128 pixels with no quiet zone and human-readable mode enabled. The binary PNG output is base64-encoded and embedded as a data URI in the HTML-to-PDF template. |
| N-U179-13 | Whether QR codes appear on invoices is governed by a company-level setting, not a per-journal toggle. The QR block is additionally suppressed when the invoice has no outstanding balance, so fully paid invoices do not display a payment QR code. |
| N-U179-14 | The invoice PDF template conditionally renders a QR code image by calling a generation method on the invoice; errors during generation are silently suppressed in report context so that a misconfigured QR setup does not prevent the PDF from being produced. |
| N-U179-15 | The Thailand accounting localization declares the EMV QR bridge module as a prerequisite and is automatically activated when the accounting module is installed for a Thai company. The localization's overrides add PromptPay proxy types, validation, merchant account encoding, and currency restrictions on top of the generic EMV infrastructure. |
| N-U179-16 | An optional payment reference may be included in the QR code via the additional data field (tag 62) when the bank account's reference-inclusion flag is enabled. The communication string is sanitized to ASCII-safe characters before encoding. Country-specific sub-tag structure within tag 62 is contributed by localization overrides; the base module leaves this block empty. |
| N-U179-17 | Before generating an EMV QR code, the system checks for four potential configuration problems: missing merchant account information, missing merchant city, missing proxy type, and missing proxy value. Country localizations may refine these checks with more specific error messages. |
| N-U179-18 | The EMV QR method is registered with a numeric sequence priority that determines its rank in the auto-selection process when the system chooses a QR method for a new invoice without an explicit method already set. |
